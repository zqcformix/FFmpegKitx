# fftools: FFmpeg's command line in libffmpegkitx_cli

`ffkx_execute` (include/ffmpegkitx.h, roadmap 6.3) runs FFmpeg's `ffmpeg` command line inside the app. Its code is FFmpeg 8.0.1's `fftools`, built here as the library `libffmpegkitx_cli.so`. libffmpegkitx_core loads that library the first time a command runs.

## Source

- **Release**: `ffmpeg-8.0.1.tar.xz` from <https://ffmpeg.org/releases/>, SHA-256 `05ee0b03119b45c0bdb4df654b96802e909e0a752f72e4fe3794f487229e5a41`. These are the same sources as the prebuilt libraries in `jniLibs/`.
- **What is taken**: everything `ffmpeg` links from `fftools/`. That is its `.c` and `.h` files, plus `graph/`, `textformat/` and `resources/`; not ffplay or ffprobe.
- **Headers**: the private headers `libavutil/thread.h`, `libm.h` and `getenv_utf8.h`, and the public `libavdevice/` headers, which ffmpeg includes even though avdevice is disabled. They sit with the other FFmpeg headers in `cpp/`.

## Local files (not from FFmpeg)

- **`config.h`**: the configuration macros that fftools and the private headers use, for Android. FFmpeg's configure would normally generate it.
- **`ffkx_build.h`**: generated by CMake.
  - `FFMPEG_CONFIGURATION` is read from the ABI's `libavutil.so`, so the banner and the library configurations match.
  - `CC_IDENT` names the compiler.
- **Resource arrays**: CMake also generates `graph.css.c` and `graph.html.c`, as FFmpeg's `bin2c` does.
- **`ffkx_fftools.h` / `ffkx_fftools.c`**:
  - `ffkx_fftools_run`, the library's only export;
  - the hooks through which a run reports to its task;
  - the options the library refuses.

## Changes to FFmpeg's files

Each changed file says so below its license header. Every change is marked `FFKX`.

| File | Change |
| --- | --- |
| `ffmpeg.c` | `main` → `ffkx_ffmpeg_main`. Refuses process-wide options before doing anything. `term_init` installs no signal handlers and leaves the terminal alone. Cancellation interrupts I/O until transcoding starts, then stops the main loop so the outputs are finished, as on `q`. Their I/O is still interrupted if finishing stalls for 3 s. The main loop wakes at least every 100 ms. `ffkx_input_int_cb` is the input callback, which also honours cancellation while transcoding. `ffmpeg_cleanup` closes `-progress`'s output. `print_report` reports progress to the task; its statics move to file scope. `ffkx_reset_ffmpeg` |
| `ffmpeg_opt.c` | An existing output without `-y` fails with `EEXIST` instead of exiting with code 0. `ffkx_reset_ffmpeg_opt`, which also turns stdin interaction off |
| `cmdutils.c` | Ignores the `FFREPORT` environment variable. `ffkx_locate_options`, `ffkx_reset_cmdutils` |
| `opt_common.c`, `ffmpeg_hw.c`, `ffmpeg_mux_init.c` | Reset functions |
| `ffmpeg.h` | Declares `ffkx_input_int_cb` |
| `ffmpeg_demux.c` | Inputs use `ffkx_input_int_cb`. A nonblocking input without data (EAGAIN) stops retrying once the task is cancelled |
| `ffmpeg_sched.c` | Each worker thread reports its start and end, so its FFmpeg lines go to the task's log |

**Why the resets**: fftools keep their state in globals and file statics, about 70 of them. A process runs `ffmpeg` once; a library runs it many times. So before each run, every global goes back to its initial value. Commands run one at a time, because the globals are shared and ffmpeg's worker threads also use them.

fftools are licensed under the GNU Lesser General Public License version 2.1 or later. So are `libffmpegkitx_cli` and the local files above. The rest of FFmpegKitx keeps its MIT license. Its code does not link `libffmpegkitx_cli`: it loads it at run time through `ffkx_fftools_run`.

**Upgrading FFmpeg**:
1. Take the new release's files.
2. Apply the `FFKX` changes again.
3. Compare the globals with the reset functions.
4. Check `config.h` against the macros the new sources use.
