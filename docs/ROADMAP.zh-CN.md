## 里程碑

| 阶段 | 范围 | 完成门槛 | 可并行 |
| --- | --- | --- | --- |
| M1 Android 首个编辑版本 | 第 1–4 章 | trim、关键帧对齐分割、`Uri` 输入、probe 有真实媒体测试和至少一台 ARM64 真机记录；错误模型冻结；新版本经空白消费者工程验证后发布 | native 核心、Kotlin API、测试样本 |
| M2 可靠内核 | 第 5–8 章 | 会话与取消闭环、C ABI 契约、可复现原生构建与来源清单、分层测试矩阵 | 会话运行时、C ABI、构建供应链 |
| M3 编辑增强 | 第 9–12 章 | 精确时间轴、合并、转码、音频/字幕均有解码级验证；Android 平台能力深化 | 音频/字幕、转码/硬件、Android 深化 |
| M4 Apple 与 HarmonyOS | 第 13–14 章 | 各平台有真实设备运行和消费者工程证据 | Apple、HarmonyOS 各自分支 |
| 远期候选 | 第 15 章 | 不排期；进入排期前先评估需求与维护成本 | — |

排序依据：

1. 先让 Android 用户拿到真正可用的编辑能力。Android 10+ 应用从系统选择器拿到的基本都是 `content://`，所以 `Uri` 输入属于 M1。
2. 编辑增强（M3）排在新平台（M4）之前：它对现有用户价值更高，而且在 C ABI 稳定前开始其他平台会反复返工。
3. Web、Flutter、React Native、桌面列为远期候选，避免路线图因范围过大而无法收敛。

## 第一卷 · Android 首个编辑版本（M1）

### 第 1 章　基线与接入

- [ ] **1.1 能力清单与非目标**（★；依赖：无）。交付：README 列出平台/ABI、FFmpeg 版本、可调用能力和非目标。验收：信息查询结果与实际打包的 `.so` 一致；未实现能力与未发布依赖明确标注。
- [ ] **1.2 本地模块接入与第一个媒体任务**（★；依赖：2.1）。交付：`implementation(project(":ffmpegkit"))` 示例、输入输出要求、协程调用示例。验收：新使用者按文档构建示例 App 并产出可播放片段。

### 第 2 章　快速时间裁剪与分割

- [ ] **2.1 快速时间裁剪**（★★；依赖：1.1、4.1）。交付：基于 libavformat 的 seek、流映射、时间戳重标定与 remux；结果同时返回 `requestedRange` 和实际首末包时间 `actualRange`；终点可省略（到媒体结尾）。验收：带音视频样本可解封装和解码，音画同步保持；`actualRange` 与 FFprobe 结果一致。
- [ ] **2.2 关键帧对齐的单遍分割**（★★；依赖：2.1）。交付：默认分割模式。顺序读取一遍输入，每越过一个时长边界，就在其后第一个视频关键帧处开新段（与 FFmpeg segment muxer 的切分方式相同）。验收：片段互不重叠，按序无损拼接后与原文件包序列一致；末段、整除、过短媒体、10,000 段上限都有测试；文档写明"每段 ≥ 目标时长（末段除外），按关键帧对齐"。
- [ ] **2.3 按显式时间段分割**（★★；依赖：2.1）。交付：一个输入对应多个时间范围和多份输出；确定输出顺序与失败回滚规则。验收：每份输出独立可读；相邻范围因关键帧产生的重叠有测试，不声称精确分割。
- [ ] **2.4 MP4/MOV edit list 起点**（★★★；依赖：2.1）。交付：可选模式，保留起点前的关键帧数据，用 edit list 让播放器从请求时间点开始显示（参考 ffmpeg CLI 输入 seek 加流复制写 MP4 的做法）。验收：Media3 ExoPlayer、系统 `MediaPlayer`、主流相册实测；不支持 edit list 的播放器行为单列；默认模式不受影响。
- [ ] **2.5 文件安全与排他交付**（★★；依赖：2.1）。交付：同文件检测、既有输出保护、同目录临时文件、失败与取消清理。验收：异常与并发写入不覆盖输入或既有文件；函数成功返回后才能读取输出；不支持硬链接时用排他创建后复制；清理失败附带诊断而不误报成功。
- [ ] **2.6 真实媒体回归**（★★；依赖：2.1–2.5）。交付：生成样本与验证脚本。验收：音视频、纯音频、纯视频、长 GOP、非零起始时间、VFR、B 帧、Unicode/空格路径均有结果；host 测试与设备测试分别记录。

### 第 3 章　输入来源与媒体探测

- [ ] **3.1 `File`、`Uri` 与文件描述符输入**（★★★；依赖：2.5）。交付：通过 `ParcelFileDescriptor` 加自定义 `AVIOContext` 读取 SAF/MediaStore 内容；区分可 seek 与不可 seek 来源；输出到 `Uri` 时要求以 `"rw"` 打开的可 seek 描述符（MP4 封装需要回写头部）。验收：系统文件选择器、照片选择器、MediaStore、云盘来源实测；不把 `content://` 当作文件路径；出错时无描述符泄漏。
- [ ] **3.2 结构化 `probe`**（★★；依赖：3.1）。交付：格式、时长、流、编码、尺寸、帧率、旋转、声道；缺失值保留为未知。验收：与固定版本 FFprobe 交叉核对；未知时长不伪造为零。字幕、metadata 等完整字段随 9.2 扩充。

### 第 4 章　Kotlin API、错误模型与首个发布

- [ ] **4.1 `Duration` 与强类型范围**（★；依赖：1.1）。交付：`TimeRange(start, endExclusive)`，终点可省略；拒绝负数、无穷值、溢出和非整数微秒。验收：非法值在执行前抛 `IllegalArgumentException`。
- [ ] **4.2 挂起函数与扩展**（★★；依赖：2.1、3.1）。交付：`FFmpeg.trim`/`FFmpeg.split` 挂起入口，`File` 与 `Uri` 扩展，自动切换到 IO 调度器。验收：主线程不做媒体 I/O；协程取消会通知原生任务，清理完成后才结束。
- [ ] **4.3 错误模型**（★★；依赖：4.1）。交付：`FFmpegException` 带 `reason` 枚举和原生错误码；取消不包装。验收：输入缺失、权限、已有输出、不支持的媒体、损坏媒体、原生错误均可区分；**首次发布前冻结**，之后只增不改。
- [ ] **4.4 首个编辑版本发布**（★★；依赖：2.6、4.1–4.3）。交付：按[发布清单](RELEASES.zh-CN.md)统一版本号、使用固定的 NDK、通过 `verifyNativeAlignment`、补齐 LICENSE 与第三方声明。验收：空白消费者工程从 JitPack 解析新版本，并在 ARM64 真机与 x86_64 模拟器上运行 trim/split。

## 第二卷 · 可靠内核（M2）

### 第 5 章　会话、事件与取消

- [ ] **5.1 会话状态机**（★★★；依赖：2.5）。交付：唯一任务 ID，等待/执行/成功/失败/取消状态，输出与耗时；终态只发一次。验收：并行任务不串结果；取消完成与失败的优先级确定。
- [ ] **5.2 结构化进度与日志**（★★★；依赖：5.1、3.2）。交付：已处理时间、目标时长、字节、速度、受限日志缓冲、脱敏选项。验收：未知时长显示不定进度，终态正确；日志不会无限占内存，也不会跨任务误归属。
- [ ] **5.3 可中断 I/O 与取消闭环**（★★★；依赖：5.1）。交付：原子取消标记、`AVIOInterruptCB`、超时、资源回收与回调生命周期。验收：读取卡住、队列等待、写入途中均可取消；取消后没有迟到的成功回调。
- [ ] **5.4 并发额度与历史策略**（★★★；依赖：5.1–5.3）。交付：按任务数和内存限制的队列、历史条数与日志上限。验收：移动端连续任务不出现无界的线程或内存增长。

### 第 6 章　稳定跨平台边界

- [ ] **6.1 从可移植 C++ 核心到 C ABI**（★★★；依赖：第 5 章）。交付：不暴露 `std::string`、异常或 FFmpeg 内部结构的公开 C 头文件；不透明句柄、版本号、结构体大小、状态码、释放函数。验收：C、JNI、Swift、Node-API 绑定共享同一头文件；跨版本兼容测试通过。
- [ ] **6.2 线程与回调契约**（★★★；依赖：6.1）。交付：回调所在线程、用户数据释放时机、禁止重入点与安全销毁说明。验收：取消与销毁竞争时没有悬空回调；结果内存按契约只释放一次。
- [ ] **6.3 可选底层命令入口**（★★★★；依赖：第 5 章、6.1）。交付：经过隔离与可重入审计的 CLI 引擎，或明确受限的命令执行后端；参数数组接口。验收：实际运行命令、引用路径、并行隔离与取消均通过；不接受拼接字符串。

### 第 7 章　原生构建、能力与许可

- [ ] **7.1 锁定 FFmpeg 与外部库来源**（★★★；依赖：1.1）。交付：提交/版本、下载校验和、补丁、configure 参数、NDK/Clang/Xcode/OH SDK 版本与 SBOM。验收：从干净环境重建，制品可追溯；当前预构建库的未知来源项显式记录。
- [ ] **7.2 能力查询**（★★；依赖：3.2）。交付：实际可用的 demuxer/muxer/decoder/encoder/filter/hw device 清单。验收：缺编码器或字体等依赖时，任务启动前给出可操作的错误。
- [ ] **7.3 最小功能包与可选能力**（★★★；依赖：7.1、7.2）。交付：基础包、字幕/滤镜扩展、硬件支持和受许可约束的变体。当前未压缩 `.so` 每 ABI 约 20–27 MB，其中 libavcodec 与 libavfilter 占大头。验收：同一应用不会重复打包冲突的 FFmpeg 符号；体积与能力清单可核查。
- [ ] **7.4 许可与供应链交付**（★★★；依赖：7.1）。交付：本项目代码许可与 FFmpeg/第三方库许可分开说明，附 notices、源代码与重新链接所需材料。验收：实际启用项与链接方式和分发声明一致；不用根目录 MIT 概括全部原生二进制。

### 第 8 章　测试、性能与版本

- [ ] **8.1 分层测试矩阵**（★★★；依赖：随各章接入，M1 起建立 host 真实媒体测试）。交付：参数单测、native 真实媒体测试、绑定测试、设备测试、消费者接入测试。验收：报告写明 FFmpeg/工具链/ABI/设备与样本来源；按解码语义验证，不只断言文件存在或字节相等。
- [ ] **8.2 性能、稳定性与升级**（★★★★；依赖：8.1）。交付：耗时/内存/体积基线、长时间取消与并发压力测试、FFmpeg 升级兼容清单。验收：升级后的功能、ABI、许可变化和媒体差异可追踪。
- [ ] **8.3 版本与 SemVer**（★★★；依赖：7.4）。交付：源码标签、制品校验和、变更日志与迁移指南；原生核心与 facade 的版本对应关系。验收：每个公开接入示例都由空白消费者工程验证。

## 第三卷 · 编辑增强（M3）

### 第 9 章　合并、换封装与流选择

- [ ] **9.1 同参数文件合并**（★★★；依赖：3.2、第 5 章）。交付：格式兼容性检查、时间轴拼接、音视频同步处理。验收：不兼容的流被拒绝或要求转码；B 帧、音轨缺失、重复时间戳有回归测试。
- [ ] **9.2 换封装与流选择**（★★；依赖：7.2）。交付：显式选择音轨/字幕、metadata 保留策略、必要的 bitstream filter；probe 补齐字幕与 metadata 字段。验收：不兼容的容器/编码组合准确报错；不静默丢弃用户选定的轨道。

### 第 10 章　精确裁剪、画面处理与转码

- [ ] **10.1 精确时间裁剪**（★★★★；依赖：第 5 章、7.2）。交付：解码—滤镜—编码管线、音频 sample 边界、编码配置与取消。验收：以解码后的时间轴校验容差；与快速模式分别说明性能和画质代价。
- [ ] **10.2 Smart cut**（★★★★；依赖：10.1）。交付：只重编码起点所在的 GOP，其余部分流复制；编码参数与源流匹配（profile、level、参数集），拼接点时间戳连续。验收：多款播放器无花屏；参数无法匹配时回退到 10.1 并说明原因。
- [ ] **10.3 画面裁剪、缩放、旋转与缩略图**（★★★；依赖：10.1）。交付：像素区域、纵横比、旋转 metadata、像素格式与对齐验证。验收：输出尺寸和实际可见区域正确，越界输入被拒绝。
- [ ] **10.4 转码与压缩预设**（★★★★；依赖：7.2、10.1）。交付：容器、编码器、质量/码率/尺寸约束、软件与硬件选择及回退。验收：明确质量与文件大小的关系，不承诺任意素材都能精确压到指定字节数。

### 第 11 章　音频与字幕

- [ ] **11.1 音频提取、静音、混音、变速与响度**（★★★；依赖：9.2、10.1）。交付：复制与重编码两条路径，声道布局与采样率策略。验收：样本数、时长、峰值有检测；变速后音视频同步。
- [ ] **11.2 字幕封装、烧录与字体资源**（★★★★；依赖：7.3、10.1）。交付：SRT/ASS、软字幕与 libass 烧录、显式字体目录及许可说明。验收：中文、RTL、换行、时间同步、缺字回退都有视觉和时间轴样本。

### 第 12 章　Android 平台深化

- [ ] **12.1 Flow 会话与结构化结果**（★★★；依赖：4.2、第 5 章）。交付：`Flow`/`StateFlow` 事件、`sealed` 结果、按需提供的 DSL。验收：结构化并发有效，收集者退出不泄漏；不强迫所有场景使用 DSL。
- [ ] **12.2 Java 编辑入口**（★★；依赖：4.3）。交付：Java 友好的同步/异步编辑门面与普通时间类型。验收：以实际 Java 消费者代码验证后才勾选。
- [ ] **12.3 Compose、生命周期与长任务**（★★★；依赖：12.1）。交付：ViewModel 示例、进度与取消 UI；按 Android 版本选择前台服务或 WorkManager。验收：旋转、退后台、进程被回收都有明确行为；不声称协程本身可跨进程存活。
- [ ] **12.4 MediaCodec 硬件编解码**（★★★★；依赖：7.2、10.4）。交付：能力查询与硬件回退、混淆配置。验收：至少一台真实 ARM64 设备和 x86_64 模拟器；三 ABI 构建只证明打包，不能代替设备运行测试。

## 第四卷 · Apple 与 HarmonyOS（M4）

### 第 13 章　iOS / iPadOS / macOS / Swift

- [ ] **13.1 Apple 构建与 SwiftPM**（★★★★；依赖：第 6、7 章）。交付：区分设备与模拟器 slice 的 XCFramework、Swift facade 与 `Package.swift`、校验和与 deployment target。验收：macOS CI 上 Xcode 实际链接并运行；Linux 上编译通过不能代替。
- [ ] **13.2 Swift 并发与资源扩展**（★★★；依赖：第 5 章、13.1）。交付：`async throws`、`AsyncStream`、`actor` 会话、`URL` 扩展；取消映射与 `Sendable` 审查。验收：`Task.cancel()` 能传到底层；流结束时释放观察者；不在主 actor 处理媒体。

进入排期前先回答三个问题：是否有明确的用户需求；现成方案（如 ffmpeg.wasm）能否满足；长期维护成本由谁承担。
